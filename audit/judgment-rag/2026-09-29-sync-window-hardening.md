# 判決增量同步截止與重試收斂（2026-09-29）

## 問題

原本排程允許 06:00 前啟動，單次最長三小時，且 systemd 對設定錯誤與超出時段都會持續重試。這可能讓同步跨出預定的清晨作業時段，或在無法自行恢復的設定錯誤上反覆啟動。

## 修正

- 預設只允許 02:00 至 05:30 開始同步。
- 接近 05:30 時，把 timeout 自動縮短為剩餘秒數。
- systemd 對設定錯誤（exit 2）及超出時段（exit 3）停止重試。
- 其他暫時性失敗仍每 10 分鐘重試，但每小時最多啟動三次。
- 保留可設定時段與人工明確覆寫，供官方服務時間變更及受控驗收使用。

## 驗證邊界

測試使用假的時間、Docker 與 timeout，驗證 05:30 不會呼叫 Docker、05:29:59 只允許一秒執行，以及失敗證據仍保留原 exit code。這不是正式主機上的真實司法院 API 或排程觸發證據。
